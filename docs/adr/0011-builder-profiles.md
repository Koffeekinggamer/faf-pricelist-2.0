# Builder Profiles — per-builder learned rules, not hardcoded

Builders differ in how their price lists express options, categories, and parse quirks. Rather than hardcode one builder's conventions in the repository/search helper, each builder gets a **Builder Profile**: a persistent record of what we've learned about that builder, consumed by two places — the **Drop files** import (so re-importing/updating a builder is seamless and consistent) and the **search/upcharge helper** (so option upcharges use that builder's real vocabulary).

A profile holds the builder-specific bits that vary: option **charge shapes** (flat `$`, `%` via `addon_pct`, or per-category), **category synonyms**, **item→category overrides** (to resolve the `approx` matches from ADR-0008 follow-up), and **parse hints** (which columns are options/addons, markup/multiplier rules, finish handling). Values are auto-learned on import where derivable and hand-tunable for the rest.

**What lives where (locked):** the profile stores **only durable rules** — category synonyms, item→category overrides, per-option eligibility, parse hints, and charge *shapes* (flat `$` / `%` / per-category). **Actual dollar amounts and the live category/charge list stay in the DB** and refresh on every re-import, so git never holds stale prices and search/upcharge always reads current charges from SQLite.

**Drop write (locked):** on a successful Drop-files Load, newly learned durable rules **auto-update** that builder's profile JSON. Charges themselves are never written into the profile. **Where:** auto-update runs on **local/Mac** Drop only → commit the JSON → deploy; production Drop on Fly **reads** shipped profiles and never writes (container FS is ephemeral; Fly volume stays catalog-only per ADR-0005).

**Storage:** versioned JSON in the repo at `config/builder_profiles/<vendor>.json`, keyed by the canonical vendor name (`standardize.resolve_builder_vendor`). Chosen over a DB table because it is flexible, diffable/reviewable in git, survives DB resets, and onboarding a builder never requires a code change. The private catalog itself stays in the gitignored DB / on Fly (ADR-0005) — only the *rules* live in the repo.

J&M Woodworking is the first profile: today's hardcoded J&M option/category vocabulary migrates into it unchanged, so search-upcharge behavior does not regress while the system generalizes.

**Named parser (locked):** after a builder is uploaded and the Drop looks right, Load writes `parser.importer` (plus filename hints and layouts seen) onto that builder's profile, keyed by the canonical vendor name. Every factory in the master price book has its own reader id — shape-specific where the book needs it, catalog-token readers wrapping the generic unpivot otherwise — so the next Drop for that factory runs the same parser. Filename hints are factory names, never Viztech `Download_NNNNN` stems. Zero rows falls through to the layout guesser and Load refreshes the lock. Fly Drop reads shipped profiles and does not write.

**A settled builder keeps its own reader (locked):** every future upload for a builder that already has a named parser MUST parse under that parser. Two guards enforce it. `save_named_parser` refuses to overwrite a specific importer with `generic`/`pdf`, so a fallthrough Load can never downgrade a settled lock. And when the locked reader does not read the book, Drop reports the miss (`locked_parser` vs `detected_importer`) and Christina blocks the Load for review rather than letting the catalog take layout-guessed rows under that builder's name. New builders still start on the guesser; only a downgrade of a settled lock is refused. `tests/test_builder_parser_contract.py` holds the contract per builder — shipped importer, next-year filename resolution, no-downgrade, and the block — and parses the real book when it is on the machine.

**Deep Drop files module (shipped):** Builder reader identity, detection, dispatch, and layout ownership live in one explicit registry. A new named reader is registered once and is then used by locked runs, first-time detection, fallback tagging, and contract tests. The Drop parse session stores a versioned, typed per-file outcome: reader lock, detected reader, layouts, variants, rows, and an authoritative readiness verdict. Old unversioned sessions are invalid and require Re-parse.

**Load gate and partial batches (locked):** readiness is enforced by the Load operation, not inferred from Christina's prose. Parse errors, zero rows, severe Species loss, a settled-reader miss, and a missed option block all block that Builder. Other ready Builders in the same Drop may still Load. The UI cannot bypass the gate by seeing fallback rows. Christina reads the gate's verdict instead of re-deriving it, so she can never recommend a Load the gate blocks.

**The option-block gate counts the source, not the output (locked):** a builder whose book prices options must Load with addon rows. The expected count belongs to the reader that ran — `WorkbookImportResult.expected_option_lines`, populated on a scan pass that is deliberately independent of the pass that builds the rows. A reader that stops emitting addons therefore reports "N expected, 0 parsed" and is blocked, instead of comparing a number against itself and passing. Readers with no option block leave the count at 0 and are unaffected; `ImportService` reads the field and knows nothing about any one builder.

**Catalog-first profile persistence (locked):** each ready Builder commits to the master price book before safe parser metadata is written. If the local profile write fails, the catalog remains loaded and Load returns a blocking warning until the parser lock is repaired. Fly remains profile-read-only. Safe learned metadata is limited to importer id, source filename, derived filename hints, observed layouts, and lock state.

**One Load operation (shipped):** Streamlit passes confirmed file index, Builder name, and multiplier to `PriceBookService`. That operation owns same-builder concatenation, readiness, wholesale fingerprint skip, `replace_vendor`, multiplier binding, parser lock, and session clearing. Several files bound to one builder become one catalog (Criswell Bedroom's four books). The removed parallel single-file Drop path can no longer drift from session parsing.

**Option groups — alternatives never stack (locked):** some option families are one choice, not a stack of checkboxes. A profile may declare `option_groups` entries (`name`, `selection: single`, `match` regex). Picking a member of a single-select group drops the other members of that group: the Options panel unchecks the siblings, and `PriceBookService.search` re-resolves the selection so an API or stale widget state can never price two members at once. Last pick wins. FN Chair has **finish category** (`Cat. 1/2/3`) and **fabric tier** groups. Artisan Chairs has separate **upholstered seat** and **wood seat** groups; modifiers such as nail heads remain stackable, and kick plates carry quantity because the source price is per plate. Finished is the search default; **Unfinished** is a finish-state Option (`finish_as_option`) for every builder whose catalog lists unfinished — checking it switches the wholesale row instead of stacking a dollar adder. A profile may override the option label; otherwise Search injects `Unfinished` from the catalog. The Finish dropdown stays hidden. Stacking members inside one family inflates the price; selecting one member from separate families remains valid. Builders with no groups keep the generic stackable behavior.

**Groups are bound to real option keys by test (locked):** a group's `match` regex points at strings a parser produces, and the parser does not know the regex exists — so a relabelled book can unbind a group silently and let two alternative prices stack. `tests/test_option_group_contract.py` binds them: every shipped single-select group must catch at least two option keys the builder's own reader actually produced (from the loaded catalog, or from the live book when the catalog is absent), and no option key may belong to two groups. Rename an option in next year's book and the contract fails instead of the floor overcharging.

**First slice (shipped):** search/upcharge reads `config/builder_profiles/j-and-m-woodworking.json`. **Drop read/write of the named parser is now live** — kill test: lock a parser on Load, re-drop a file that resolves to that builder, same importer runs without hand-picking a layout.

**Status:** accepted
